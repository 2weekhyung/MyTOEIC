# 서버 DB 적용 결과

2026-11-01(한국 시간), 사용자 승인 후 로컬 프로젝트에서 기존 서버의 전용 `mytoeic` DB를 V2에서 V4로 업그레이드했다. 연결 정보와 비밀번호는 이 문서에 포함하지 않는다.

후속 웹사이트 작업에서 준비한 V5 내용 보완은 사용자가 코드만 준비하도록 지시했으므로 서버에 적용하지 않았다. 마지막 읽기 전용 확인에서도 테이블 27개와 Flyway V4를 확인했다. 이후 런타임 계정 권한 설정과 TLS 접속, Linux 앱·HTTPS 배포, 최초 사이트 계정 생성을 완료했다. 배포 과정에서도 자동 Flyway는 껐으며 V5는 보류 상태다. [배포 기록](DEPLOYMENT.md)을 참고한다.

## 적용 및 검증

- MySQL 8.0.46에 JDBC/TLS로 실제 연결 성공.
- 변경 전 기본 테이블 24개(학습 테이블 23개와 Flyway 이력)를 단일 트랜잭션 mysqldump로 백업했다.
- gzip 무결성 및 SHA-256 체크섬을 확인했다. 백업은 Git에서 제외된 `backups/`에 보관한다.
- 서버와 분리된 로컬 MySQL 컨테이너의 새 DB에 백업을 복원했다. 원본 행 전체의 PK 및 JSON 행 SHA-256 값과 모두 일치했다. 포트는 외부에 공개하지 않았고 검증용 컨테이너만 제거했다.
- 기존 V1/V2 체크섬 검증 후 V3(지문 테이블 3개와 문제 종류 CHECK 확장), V4(RC 콘텐츠)를 적용했다.
- 적용 후 원래 있던 모든 행을 변경 전 SHA-256 값과 비교해 동일함을 확인했다. 기존 PK도 그대로다.
- Flyway 재실행 결과 V4 최신 상태이며 추가 마이그레이션 0개였다.
- `infra/mysql/verify-rc.sql`을 실제 서버에서 실행해 아래 수량과 세트별 연결을 확인했다.

| 항목 | 수량 |
|---|---:|
| 문법 강의 | 10 |
| 문법 예문 | 30 |
| 문법 연습 | 20 |
| Part 5 | 50 |
| Part 6 | 16 |
| Part 7 | 30 |
| 단어 | 200 |
| RC 지문 세트 | 12 |
| RC 지문 | 16 |
| 지문 세트와 문제 연결 | 46 |

백업 파일은 `backups/mytoeic-pre-v3-20261101-153343.sql.gz`이며 동일 이름의 `.sha256` 파일이 있다. 복원 검증 결과는 `backups/restore-verification.txt`, 원본 행 비교값은 `backups/pre-v3-row-hashes.tsv`와 `backups/post-v4-original-row-hashes.tsv`에 보관한다. 이 파일들은 개인 데이터이므로 Git에서 제외한다.

## 이번 작업의 범위

서버의 다른 서비스 DB에는 쿼리를 실행하지 않았다. 변경 전 `user_account`와 학습 이력 테이블은 비어 있었다. 이번 DB 업그레이드 이후 별도 배포 단계에서 런타임 권한을 적용하고 사용자가 브라우저에서 첫 사이트 계정을 생성했다. DB 업그레이드와 계정 생성은 별도 작업이며 기존 학습 기록을 초기화하지 않았다.
